# Filter+ low-CPU DSP notes

This describes the shared kernels behind the Filter+ low-CPU bank. The stock
SVF/comb paths and the low-CPU additions live in `shared/df_dsp.c` and
`shared/filter_dsp.s`.

## Mode map

| TYPE slot | family |
|---|---|
| BP, BP2 | trapezoidal SVF band-pass |
| COMB, TRASH | full feedback combs (fractional delay, damping, smoothing) |
| LP1, HP1 | 1-pole TPT |
| LP4-, HP4- | four cascaded TPT 1-poles |
| LP2, HP2, NOTCH | 2-pole SVF output mixes |
| COMB-, TRASH- | integer-delay lofi combs |

## 1-pole TPT

`LC_OP_G[fi]` is `g / (1 + g)` in Q31, where `g = tan(pi f / fs)`. Per sample:

```text
v = (x - s) * G
y = v + s
s = y + v
```

LP1 returns `y`; HP1 returns `x - y`. LP4-/HP4- run four of these in cascade
with the same `G` and four independent states. The `G` table is generated by:

```sh
python tools/gen_lc_tables.py
```

## 2-pole SVF mixes

`struct df_coef` is `{ a1, a2, a3, c0, c1, c2 }`. `df_mode_coef` sets the
output mix:

| mode | c0 | c1 | c2 |
|---|---|---|---|
| BP/BP2 | -ONE27 | k | 0 |
| LP | -ONE27 | 0 | ONE27 |
| HP | 0 | -k | -ONE27 |
| NOTCH | 0 | -k | 0 |

The original `digifilter_svf` / `digifilter_svf4` kernels omit the `c2*v2`
MAC (the BP path). The `_mix` variants add it. `df_svf_run` chooses the normal
kernel for BP/BP2 and the mix kernel for LP/HP/NOTCH; the coefficient cache key
includes the mode so an output change cannot reuse the wrong mix.

## Integer-delay lofi comb

`df_lc_run` handles COMB-/TRASH- with a fixed integer delay:

```text
delay = COMB_DELAY[fi] / (1 or 2)
g     = fb * (ONE27 / 32) * 31 / 127
y     = x + ((g >> 12) * (delay_read >> 11)) >> 4
```

There is no fractional read, per-sample smoothing or damping. It reuses the
existing per-voice 256-word comb buffer but has its own init/position state;
`df_reset` clears both comb variants.

## CPU

Cycles per voice per 32-sample block, DT adapter, digiemu cycle model:

| mode | static | swept |
|---|---:|---:|
| LP1 | 606 | 593 |
| HP1 | 671 | 665 |
| TRASH- | 1035 | 1035 |
| COMB- | 1072 | 1044 |
| BP2 | 1318 | 2294 |
| BP | 1346 | 2363 |
| NOTCH | 1465 | 2403 |
| HP2 | 1480 | 2423 |
| LP2 | 1481 | 2421 |
| LP4- | 1562 | 1556 |
| HP4- | 1633 | 1626 |
| TRASH | 2023 | 2022 |
| COMB | 2037 | 2022 |

Stock reference: 2603 cycles/voice/block, measured from the stock DT 1.53
multimode filter (20,821 cycles per 8-voice block, 18,121 instructions per
block / 8 = ~2265 instructions per voice). The 1.54 stock filter per-TYPE
costs and the DN adapter overhead were not separately benched.

## Tradeoffs and next steps

- LP2/HP2/NOTCH use the SVF rather than a DF2T biquad, keeping the coefficient
  footprint small. A DF2T kernel could be cheaper but needs a new coefficient
  table and a new kernel.
- COMB-/TRASH- are deliberately lofi; they are not drop-in replacements for
  COMB/TRASH when damping or fractional pitch is needed.
- The fastest modes are the 1-pole and lofi-comb paths; the BP/BP2/
  LP2/HP2/NOTCH paths are dominated by the SVF kernel when the cutoff is
  swept.
- Hardware validation and per-TYPE stock measurements are the main open items.
